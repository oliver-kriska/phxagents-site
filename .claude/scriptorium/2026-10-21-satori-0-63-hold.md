# satori 0.30–0.63: hold at 0.29.x

**Verdict (2026-10-21): hold at 0.29.1.** Re-evaluate when the release pace settles and the fflate pin moves past the advisory.

Context: phxagents-site renders OG cards with satori → sharp (see the satori+sharp rasterize note). `npm outdated` showed 0.29.1 → 0.63.2.

Why not upgrade:

- **Churn:** 58 releases in October 2026 alone (0.30 through 0.63 within days), against roughly 1–9 a month before.
- **Engine swap:** 0.63 drops `yoga-layout` and adds `harfbuzzjs`. The layout and text-shaping engine changed, which is exactly what an OG card depends on.
- **Reintroduces a vuln:** 0.63.2 pins `fflate@0.7.3`, inside GHSA-px8p-9vwx-vf98 (fflate 0.7.0–0.7.4, unzipSync infinite loop on malformed ZIP64). On 0.29.1, `npm audit fix` resolves the transitive fflate to a patched version. On 0.63 the exact pin blocks that.
- Maintainers and repo are still vercel/satori (shuding et al.), so there's no takeover signal. This is a stability call, not a compromise call.

Same session, also held: **TypeScript 7**. `@astrojs/check@0.9.11` peers on `typescript ^5 || ^6`, and TS 7 (native) exposes no classic compiler API (`exports` only `./unstable/*`), so the Astro language server can't use it.
